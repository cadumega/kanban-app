🔧 Como funciona por trás dos panos?

O Backend: O "Cérebro" da Aplicação

Imagine um restaurante: o Frontend é o salão onde você vê o cardápio e faz pedidos.
O Backend é a cozinha onde tudo é preparado e armazenado.

🏗️ Arquitetura do Sistema

🖥️

Frontend

Interface visual que você vê e usa

React + TypeScript

⚙️

Backend

Processa pedidos e gerencia dados

Node.js + Express

💾

Banco de Dados

Armazena todas as informações

SQLite

🟢 Node.js: O que é?

🖥️ Frontend (React)

O que faz: Mostra a interface bonita

Onde roda: No navegador do usuário

Exemplo: Quando você vê os cards de tarefas

⚙️ Backend (Node.js)

O que faz: Processa pedidos e gerencia dados

Onde roda: No servidor (sua máquina ou nuvem)

Exemplo: Quando você cria uma tarefa, ele salva no banco

Node.js é como um garçom de restaurante: recebe os pedidos (do frontend) e leva para a cozinha (banco de dados), depois traz a resposta de volta!

📁 Estrutura do Backend

// Estrutura organizada em pastas: backend/ ├── index.js ← Servidor principal (o "garçom") ├── database/ │ └── init.js ← Configura o banco de dados └── routes/ ├── columns.js ← Cuida das colunas ├── tasks.js ← Cuida das tarefas └── categories.js ← Cuida das categorias

Cada arquivo tem uma responsabilidade: organização clara e fácil de manter!

💡 Exemplo Prático: Criar uma Tarefa

1. Você preenche o formulário
Título: "Fazer relatório"
Prioridade: Alta
→
2. Frontend envia para o Backend
POST /api/tasks
{ title: "Fazer relatório", priority: "alta" }
→
3. Backend (Node.js) recebe e processa
Valida os dados, gera um ID único, prepara para salvar
→
4. Banco de dados salva
A tarefa fica armazenada permanentemente

🛠️ Ferramentas do Backend

Express

O "garçom" que recebe e direciona pedidos HTTP

SQLite

A "geladeira" que guarda todos os dados de forma segura

UUID

Gera códigos únicos para cada tarefa (tipo RG)

CORS

Permite que frontend e backend conversem sem bloqueios
